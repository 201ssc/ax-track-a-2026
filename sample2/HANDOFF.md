# 공유본 현재 상태와 인수인계

기준: 2026-10-23. 새 작업은 [INDEX.md](INDEX.md)에서 담당 규칙·수정 범위·검사를 먼저 확인합니다. 과거 합의는 [DECISIONS.md](DECISIONS.md)의 변경 이력이며 현재 규칙은 인덱스에 연결한 담당 문서를 따릅니다.

## 현재 완료한 기능

- 기존 다이어리 UI와 기록 규칙에 Node HTTP API·SQLite를 연결했습니다. 수동 관리·날짜별 기록·제목·일정·리포트가 같은 서버 상태를 사용합니다.
- Gemini는 루틴 항목 자체의 추가·삭제 의도와 이름을 해석합니다. 서버가 대상을 검증하고 변경 제안을 저장하며, 사용자가 확인한 뒤 공통 명령으로 반영합니다.
- 확인 전 불변, 취소·만료·수정 충돌, 중복 확인·요청 재시도, 저장 실패 시 입력 유지, 삭제 후 과거 문항·답변·집계를 보존합니다.
- 일정·목차·수치 조회는 기존 각본 기능입니다. 대화 원문은 저장하거나 다음 요청에 전달하지 않습니다.
- 사용자 직접 사용감 확인과 Gemini 연결 후 루틴 삭제 요청 성공 확인을 마쳤습니다. 개인용 첫 루틴 관리 MVP 완료이며 모든 자연어 표현의 품질 확인을 뜻하지 않습니다.

## 실행과 자료

저장소 루트에서 `npm --prefix sample2 start`, 주소는 http://localhost:8787/sample2/ 입니다. Node 24.18.1 이상 24 계열을 사용합니다. 실행에는 별도 의존성 설치·빌드가 없습니다.

공유본에는 실제 `.env`·API 키·사용자 DB를 넣지 않았습니다. `.env.example`을 복사해 각자 설정합니다. 최초 생성하는 DB에만 가상 예시를 넣으며 기존 DB를 재초기화하지 않습니다. 기본 DB는 OS 사용자 데이터 경로의 `iruo-habit-diary/diary.sqlite`입니다. 다른 실행본과 분리하려면 `DIARY_DB_PATH`를 지정합니다.

Gemini에 보내는 자료는 이번 요청과 현재 목차·항목 이름뿐입니다. 날짜별 답변·회고·점수·일정·대화 이력·DB·항목 ID는 보내지 않습니다. 모델 오류를 각본 쓰기로 전환하지 않습니다.

## 최근 수정과 검증 구분

- “생활 루틴에 명상 항목 제거해줘”가 목데이터 응답으로 끝나는 오류를 수정했습니다. 기존 각본이 목차까지 항목 이름으로 검색해 실패하면 성공 제안만 보던 서버 분기가 Gemini를 건너뛰었습니다. 이제 루틴 요청 종류를 표시해 이름 검색 실패·검증 안내도 Gemini로 보냅니다. 클라이언트 캐시 버전은 `f59d64e0da08`입니다.
- 개발 원본에서 자동 검사 62개를 통과했습니다. 이전 전체 브라우저 9종 이후 이 수정과 관련된 `gemini`, `chat`, `startup` 3종을 다시 통과했습니다. 이 검사들은 실제 모델을 호출하지 않습니다.
- 실제 Gemini는 최초 연결 1건, 통합 시나리오 4건, 정확한 사용자 추가·삭제 문장 회귀 2건을 검사했습니다. 모두 합성 자료·임시 DB를 사용했습니다. 제안/확인·반복 확인·모호한 요청·없는 항목·삭제 후 과거 보존을 확인했으나 폭넓은 해석 품질 검증은 아닙니다.
- 기본 서버 재시작 전후 사용자 상태·revision 불변을 확인했고, 이후 사용자가 수정된 삭제 요청 성공을 확인했습니다. 실제 사용자 기록은 공유본에 포함하지 않습니다.
- 공유본 검증 결과는 아래에 추가합니다. 공유를 위해 새 실제 모델 호출은 필요하지 않습니다.
