# 습관 다이어리 검증 기준

검사는 이번 변경과 연결되는 규칙을 확인하기 위해 선택한다. 아래는 작업 종류별 기준이며 실행 순서표가 아니다. 실제 실행 여부와 과거 검증 기록은 [HANDOFF.md](../HANDOFF.md)에 구분해 남긴다.

## 현재 실행 가능한 검사

모든 명령의 작업 위치는 저장소 루트다.

```bash
node --test sample2/tests/*.test.mjs
```

브라우저 검사는 각자 임시 DB·로컬 서버를 자동 준비한다. 사용자 실행 서버를 재사용하지 않는다.

Playwright와 브라우저 경로는 환경에서 확인한다. 아래는 기존 환경에서 사용한 경로이며 없으면 현재 설치 위치로 대체한다.

```bash
PLAYWRIGHT_MODULE=/설치경로/node_modules/playwright \
BROWSER_EXECUTABLE=/설치경로/chrome-headless-shell \
node sample2/tests/management.cjs
```

검사마다 분리된 브라우저 컨텍스트를 사용한다. 사용자 브라우저의 실제 저장소에 테스트를 실행하지 않는다. `server-fixture.cjs`가 임의 포트와 임시 DB를 제공하며 테스트 종료 시 제거한다.

| 변경 종류 | 기존 검사 | 특히 확인할 동작 |
| --- | --- | --- |
| 기록·모델 | `model.test.mjs`, `browser.cjs` | O/X 완료, 미기록 구분, 일부 저장, 수정·삭제, 과거 구성 보존 |
| 항목 관리·삭제 | `model.test.mjs`, `management.cjs` | 중지/재개/삭제 구분, 과거 답변·집계 유지, 당일 후속 저장 후 보존 |
| 채팅 | `chat.test.mjs`, `chat.cjs` | 확인 전 불변, 취소, 동명 선택, 오래된 제안, 저장 실패 |
| 제목·일정 | `model.test.mjs`, `messages.cjs` | 전날 답변 우선, 양방향 수정/삭제, 체크 독립, 일정 날짜 이동 |
| 미래 날짜 | `future-dates.cjs` | 미래 조회·계획 허용, 응답·완료 체크 제한, 선택 날짜 유지 |
| 예시·저장 초기화 | `prototype.test.mjs`, `prototype.cjs` | 예시 생성, 저장값 유지, 초기화 대상 제한, 초기화 이후 입력 재보존 |
| 시작·캐시 | `startup.cjs` | 모듈 실패 안내, 주소 정리 실패, 캐시 일치, 데이터 보존 |
| UI | 해당 기능의 브라우저 검사 | 320/390/1440px, 가로 넘침, 하단 탭·입력창·알림 겹침, 조회 시 저장값 불변 |
| SQLite 저장 코어 | `storage.test.mjs` | 파일 재시작·다중 프로세스 충돌·중복 요청·실패 롤백·백업 복원·과거 보존·서울 날짜 |
| HTTP·제안 | `http.test.mjs`, `chat.cjs` | v1→v2 백업·제안 확인·취소·만료·충돌·중복 확인·대상 선택·명령 교체 거절 |
| 통신·동시 수정 | `sync.cjs` | 입력 유지·응답 유실·동일 요청 재시도·두 탭 충돌·처음 API 실패 |
| Gemini 어댑터·연결 | `gemini.test.mjs`, `gemini.cjs` | 키/모델 검증·구조화 출력·권한/한도/시간 오류·이름 선택·변경 충돌·초안 유지 |
| 문서만 변경 | 링크·파일 경로·현재/목표 구분 대조 | 인덱스에서 해당 규칙과 검사까지 도달 가능한지 |

`.test.mjs`는 위 단위 테스트 명령으로 실행한다. `.cjs`는 같은 환경 변수를 사용해 파일별로 실행한다. 변경 관련 검사를 통과한 뒤 새로운 오류나 영향 범위가 없다면 불필요하게 반복하지 않는다.

현재 채팅 삭제 검사는 기록 있는 항목도 삭제하고 과거를 보존하는 계약을 따른다. 이전 localStorage 초기화 검사는 호환 단위 검사로 남고, 현재 화면은 HTTP/DB 재조회와 통신 실패를 검사한다.

## 새 루틴 도구의 완료 확인

[루틴 도구 계약](routine-tools.md)의 완료 조건을 기준으로 의미 있는 검사를 추가한다. 최소 대상은 추가·삭제 성공, 확인/취소, 동명 선택, 오래된 제안, 중복 확인, 저장 실패, 삭제 후 과거 보존이다. 대역의 정해진 결과를 그대로 재진술하는 테스트만으로 완료하지 않는다.

목표가 ‘AI 연결 전 준비’이면 테스트 대역으로 해석 결과 → 제안 → 확인 → 저장 → 재조회·화면 반영을 검증한다. 대역만 사용했다는 사실을 남긴다. 실제 제공자 호출·응답 품질·비용 검증은 아직 완료된 것이 아니다.

## 서버 연결을 구현할 때 추가할 검사

SQLite 저장 코어와 CLI는 구현됐으며 `node --test sample2/tests/storage.test.mjs`로 검사한다. HTTP·화면·채팅 제안 연결은 `http.test.mjs`와 브라우저 검사 9종으로 검증한다. [명령 계약](command-contract.md)에 실제 실행법이 있다. 아래는 현재 검사와 이후 확장에서도 유지할 완료 기준이다.

- 실제 DB에 저장하고 연결/프로세스를 다시 열어 조회한다. 메모리 저장만으로 영속성을 입증하지 않는다.
- 같은 요청 재시도와 다른 내용의 수정 충돌을 구분한다. 오래된 수정이나 제안이 최신 상태를 덮지 않는지 확인한다.
- 제목과 전날 답변처럼 함께 바뀌어야 하는 데이터를 부분 실패 상태로 남기지 않는다.
- 저장 상태와 요청 성공 기록을 같은 트랜잭션으로 검증한다. 커밋 후 응답 유실을 재현하고 같은 요청 ID 재시도가 중복 반영되지 않는지, 다른 본문으로 ID 재사용 시 충돌하는지 확인한다.
- 브라우저가 전체 상태·문항 사본을 보내 서버 검증을 우회할 수 없도록 명령별 입력 검사와 허용하지 않은 명령 거절을 확인한다.
- 새 DB에만 예시를 한 번 넣고, 재시작·날짜 변경 후 새 기록이 유지되는지 확인한다. 테스트 DB와 사용자 DB 경로를 분리하고 백업의 별도 경로 복원을 검증한다.
- 화면과 채팅이 같은 저장 기능과 집계 결과를 사용하는지 확인한다.
- 기존 브라우저 검사의 localStorage 읽기·저장 실패 주입은 서버 전환 때 API/DB 재조회·통신 실패 주입으로 바꾼다. 관리·기록·제목·일정 중 일부만 서버에 저장되는 상태를 완료로 처리하지 않는다.
- 서버와 브라우저의 시간대가 달라도 `Asia/Seoul` 날짜 기준과 자정 전후의 오늘·미래 제한이 일치하는지 확인한다.
- 현재 개인 MVP 범위만 검증했다면 여러 사용자 격리·기기 동기화까지 검증했다고 보고하지 않는다.

## 완료 보고에 남길 내용

작업 목적과 수정 파일, 적용한 규칙, 실행한 명령·결과, 사용한 저장/AI 대역 여부, 미검증 범위를 짧게 기록한다. 문서만 바뀐 작업에는 기능 테스트를 실행한 것처럼 적지 않는다. 모바일 뷰포트 검사는 실제 휴대폰 키보드 검증과 구분한다.

## 실제 Gemini 호출 검사

일반 npm test와 브라우저 검사는 실제 API 키를 쓰지 않는다. `npm --prefix sample2 run check:gemini`만 별도로 실제 호출 4건을 수행한다. 키를 읽지만 출력하지 않으며 임시 서버·합성 자료·임시 DB만 사용한다. 실제 API 비용/한도를 사용하므로 변경 검증이 필요할 때 명시적으로 실행한다. 자연어 추가·삭제, 모호/없는 대상, 확인 전 불변·확인 반복·과거 보존을 검사한다. 어댑터와 UI의 대역 검사 통과를 실제 모델 품질 통과로 합치지 않는다. 현재 결과는 HANDOFF에 남긴다.
