# 습관 다이어리 개발 규칙

이 규칙은 새 세션이나 기능 확장 때 기존 합의를 잃지 않기 위한 작업 기준이다. 가계부의 규칙 문서·기능 계약·검증 분리 방식을 참고하되, 그 저장소의 파일 수·클래스 수·서비스 수 제한을 그대로 적용하지 않는다.

## 작업을 시작할 때

1. [INDEX.md](../INDEX.md)와 [HANDOFF.md](../HANDOFF.md)에서 현재 범위·상태·남은 결정을 확인한다.
2. 인덱스의 해당 작업 행에서 규칙·코드·검증을 찾는다. 관련 코드를 읽기 전에 예전 결정만으로 동작을 추정하지 않는다.
3. `git status --short`로 기존 변경을 확인한다. 다른 작업의 변경·미추적 파일을 정리하거나 되돌리지 않는다. `sample/` 원본은 수정하지 않는다.
4. 이번 작업의 목적, 적용 규칙, 수정 범위, 완료 확인 방법을 짧게 밝힌다. 이미 요청된 범위의 통상적인 수정에는 반복 승인을 요구하지 않는다.

사용자가 문서 검토나 논의만 요청했다면 구현으로 넘어가지 않는다. 기능 추가를 요청한 경우 해당 기능을 완성하는 데 필요한 통상적인 세부 구현은 진행한다. 제품 의미를 바꾸거나 범위를 넓히는 미결정만 구분해서 논의한다.

## 코드 역할

- 화면은 입력·표시·확인 조작을 담당한다. 항목 추가·삭제·답변 보존 규칙은 공통 기능으로 모아 화면과 채팅이 공유하도록 한다.
- 요청 해석과 확정 저장을 분리한다. 실제 AI나 테스트 대역을 바꿔도 기록 규칙은 바뀌지 않게 한다.
- 숫자·기간·대상 존재·삭제 보존·입력 유효성은 코드로 처리한다. LLM 출력이나 브라우저가 보낸 문항 사본을 검증 없이 저장 기준으로 삼지 않는다.
- 저장소 접근, 외부 모델 호출, 환경 설정은 각각의 연결부로 한정한다. 서버를 선택하면 DB 접속 정보와 모델 키를 브라우저에 두지 않는다.
- 파일은 책임이 갈리는 지점에서 나눈다. 가계부의 네 계층이나 한 파일 한 클래스 규칙을 맞추려고 빈 폴더·형식적인 클래스를 만들지 않는다.
- 기술 선택은 다이어리 요구와 유지보수 비용을 기준으로 정한다. 선택 이유·대안·영향은 결정 이력에 남기고, 구현 전에는 확정으로 표시하지 않는다.

현재 화면은 표시·입력·확인을 맡고 변경은 서버 공통 명령을 사용한다. `chat.mjs`에는 해석 대역과 호환 순수 함수가 남아 있으므로 관련 기능 수정 때 함께 확인한다.

저장 코어용 공통 명령은 `commands.mjs`에 있으며 화면과 서버의 각본 채팅이 사용한다. 새 기능에서도 기록 규칙을 화면/해석기에 복제하지 않는다.

## 상태와 변경 이력

문서에는 다음을 구분한다.

| 상태 | 의미 |
| --- | --- |
| 현재 구현 | 코드에 있고 현재 실행 경로에서 사용하는 기능 |
| 확정 범위 | 사용자가 정한 제품 방향·기능 범위. 아직 구현되지 않았을 수 있음 |
| 설계 초안 | 구현을 구체화하기 위한 제안. 사용자 승인 사실로 기록하지 않음 |
| 미정 | 기술·제품 선택이 남아 있음 |
| 검증 결과 | 실제 실행한 명령·환경·결과. 문서의 과거 결과와 구분 |

새 기능 계약에 추가한 세부 설계는 초안 여부를 밝힌다. 구현으로 채택하면 현재 계약으로 갱신한다. 테스트가 통과하도록 합의된 동작을 임의로 바꾸지 않는다.

## 문서 갱신 기준

- 규칙 변경: 담당 규칙 문서에 현재 기준을 반영하고 [DECISIONS.md](../DECISIONS.md)에 변경 이유와 대체한 규칙을 추가한다. 과거 이력 자체는 삭제하지 않는다.
- 구현 변경: [README.md](../README.md)의 실제 사용 범위와 [HANDOFF.md](../HANDOFF.md)의 구현 상태를 갱신한다. 제품 규칙을 여러 문서에 다시 복사하지 않는다.
- 파일·검사 추가: [INDEX.md](../INDEX.md)의 작업별 연결과 [검증 기준](verification.md)을 갱신한다. 필요해진 시점에 해당 기능 계약을 추가한다.
- 작업 종료: 변경한 기능, 남은 차이, 실행한 검증, 미실행 검증, 다음 작업의 관련 문서 위치를 인수인계한다. 사용자와 정하지 않은 다음 작업을 자동 착수 대상으로 쓰지 않는다.
- 인덱스와 `AGENTS.md`는 읽기 경로를 제공한다. 파일 존재만으로 모든 도구가 규칙을 자동 준수하거나 테스트를 실행하는 것은 아니다. 완료 보고에서 사용한 기준과 검증 결과를 확인할 수 있어야 한다.

## 데이터와 캐시

현재 테스트 입력 정리 허용은 [제품 규칙 R6](product-rules.md#r6-예시와-테스트-입력)을 따른다. 저장 오류·모듈 캐시 문제를 해결하려고 다이어리를 자동 초기화하지 않는다.

현재 클라이언트 실행 파일을 수정하면 저장소 루트에서 `python3 sample2/update-assets.py`를 실행하고 관련 시작 검사를 한다. 문서만 수정한 경우에는 캐시 버전을 바꾸지 않는다.

커밋·푸시·외부 배포는 별도 사용자 지시가 있을 때 수행한다. 문서 정리나 로컬 구현이 배포 승인까지 뜻하지 않는다.
