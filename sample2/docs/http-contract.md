# 로컬 서버·화면·채팅 연결

현재 구현: [HTTP](../server/http.mjs), [시작](../server/start.mjs), [설정](../server/config.mjs), [화면 연결](../api.mjs), [채팅 해석 연결](../server/chat-service.mjs). Node 24.18.1 이상 24 계열에서 `npm --prefix sample2 start`로 실행한다. 기본 주소는 `http://localhost:8787/sample2/`다.

## 저장과 설정

- 화면의 기록·항목·목차·제목·일정 변경은 전부 공통 명령 → SQLite로 저장한다. 전체 상태 덮어쓰기 API는 없다. 서버 오류 때 브라우저 저장으로 전환하지 않는다.
- 새 DB에 기본 예시를 한 번 넣는다. 같은 DB를 사용하는 모든 로컬 탭·브라우저는 같은 자료를 본다. 기존 localStorage는 자동 이전·삭제하지 않는다.
- `sample2/.env`는 서버/CLI에서만 읽는다. [예시 파일](../.env.example)의 현재 사용 항목은 PORT와 선택적 절대 DIARY_DB_PATH다. 둘 다 생략 가능하다. 프로세스 환경값이 있으면 해당 값을 우선한다. `.env`는 Git 제외, `.env.example`은 공유한다.
- AI 설정은 Gemini 전용 GEMINI_API_KEY·AGENT_MODEL·AGENT_TIMEOUT_SECONDS다. 실제 Gemini 어댑터·키 검증·시간 제한을 연결했다. 키와 모델이 모두 비면 각본 대역, 하나만 있으면 시작 오류다. 요청당 최대 1회 호출하며 자동 재시도하지 않는다. 상세 데이터 범위·모델 오류·실제 검사 명령은 [Gemini 계약](gemini-contract.md)을 따른다. 키는 서버에서만 읽고 로그·브라우저·오류에 출력하지 않는다.
- 기본 DB는 사용자 데이터 디렉터리 `iruo-habit-diary/diary.sqlite`다. 저장소 밖 경로를 사용한다. 정확한 경로는 서버 시작 로그에 표시한다. 서버와 CLI는 같은 설정을 읽는다.
- 스키마 버전 1 → 2 갱신 전에 원래 DB를 `DB경로.before-v2-고유값.sqlite`로 백업한다. 상태·revision·기존 요청 결과를 보존하고 `proposals` 테이블을 추가한다. 이후 재시작은 다시 예시를 넣거나 스키마를 초기화하지 않는다.

## HTTP 계약

| 경로 | 동작 |
| --- | --- |
| `GET /api/diary` | 상태·revision·서울 기준 today/timeZone·마지막 저장 시각 |
| `POST /api/commands` | [명령 계약](command-contract.md)의 요청과 결과. 같은 ID 재시도는 같은 결과 |
| `POST /api/chat` | `{text}`만, 1~600자. 서버의 최신 상태에서 정해진 표현을 해석. `answer / choices / proposal` 반환 |
| `GET /api/proposals/:id` | 제안 상태·미리보기·만료 시각·적용 결과. 전체 대화 조회는 아님 |
| `POST /api/proposals/:id/confirm` | 빈 객체 `{}`. 서버에 저장한 명령만 확정. 임의 명령·본문 교체 거절 |
| `POST /api/proposals/:id/cancel` | 빈 객체 `{}`. 대기 제안을 취소하고 다이어리 불변 |

쓰기 요청은 application/json, 최대 1MiB다. 잘못된 JSON은 400, 다른 형식은 415, 규칙 위반은 422, 대상 없음은 404, 수정 충돌은 409다. 저장소 오류는 503과 일반 안내를 반환한다. 내부 경로·오류 상세를 응답에 담지 않는다.

서버는 127.0.0.1에 바인딩하며 허용 Host·같은 출처를 검사한다. 정적 제공은 화면에 필요한 파일 목록으로 한정한다. `.env`·DB·백업·서버 코드·저장소 전체는 웹으로 제공하지 않는다. 로컬 개인용이며 외부 배포·로그인·다중 사용자 격리 기능은 없다.

## 제안과 확인

해석 결과를 저장 명령으로 변환하고 서버가 다시 검증한 후 제안 ID와 미리보기를 보낸다. 제안 생성으로 다이어리·revision은 변하지 않는다. 같은 이름의 후보가 여러 개이면 후보별 서버 제안 ID를 보내고 사용자가 고른 것만 확인한다.

첫 Gemini 루틴 도구는 항목 추가(O/X)와 항목 삭제다. 삭제는 관리 화면과 같은 공통 기능을 호출하며 과거 문항·답변·집계를 유지한다. 기존 목차·일정·조회도 각본 호환 기능으로 유지하되 신규 AI 도구로 설명하지 않는다. 목차의 기존 일괄 중지는 `group.pause` 호환 명령이며 일반 빈 목차 삭제와 다르다.

제안은 24시간 뒤 만료된다. 확인 때 revision이 달라졌으면 재요청하고, 확정 저장·요청 결과·제안 적용을 한 트랜잭션에서 처리한다. 확인을 반복해도 한 번만 적용한다. 취소와 확인 중 먼저 확정된 상태가 유지된다. 적용 뒤 취소는 되돌리기가 아니다. 서버 재시작 뒤에도 제안 ID로 결과를 다시 조회·확인할 수 있다.

대화 화면은 메모리에만 있고 새로고침 후 복원하지 않는다. 저장된 제안과 요청 결과는 대화 기억 기능이 아니다. 현재 Gemini를 이 해석 경계에 연결했으며 확인·확정 저장은 모델에 맡기지 않는다.

## 화면의 실패·재시도

- 저장 중 중복 클릭과 입력 변경을 막는다. 성공 후 DB를 다시 읽고 창 닫기·성공 안내를 한다.
- 연결 실패·응답 유실·잘못된 응답에서는 작성 내용을 남긴다. 같은 내용을 다시 저장하면 같은 요청 ID·원래 revision을 사용해 성공 결과를 확인한다. 결과가 불확실한 동안 다른 변경 요청은 먼저 앞선 저장을 확인하도록 안내한다.
- 수정 충돌에서는 최신 자료를 다시 읽되 창과 입력을 유지한다. 사용자에게 다시 확인하게 하고 다음 저장은 새 요청 ID를 사용한다. 자동 덮어쓰기나 자동 병합은 하지 않는다.
- 새로고침은 입력창과 대화·미확정 전송 정보를 복원하지 않는다. 저장 중·응답 대기·미제출 답변이 있으면 브라우저 이탈 확인을 요청한다. 이 확인을 무시한 이탈까지 초안을 보존하는 기능은 미구현이다.
- 화면 복귀와 60초 간격으로 입력창이 닫혀 있고 저장 대기가 없을 때만 재조회한다. 날짜 판단은 서버가 제공한 서울 기준 today를 쓴다. 서버와 브라우저 OS 시간대 차이를 저장 규칙에 섞지 않는다.
- 최초 API 조회나 모듈 로딩 실패는 다시 불러오기 화면으로 안내한다. 정적 Python 서버만 켜서는 현재 앱을 사용할 수 없다.

검증은 [HTTP 검사](../tests/http.test.mjs)와 임시 DB를 직접 띄우는 브라우저 검사 9종이다. 명령은 [검증 기준](verification.md), 직접 눌러볼 항목은 [직접 테스트](manual-check.md)에 있다. 실제 모델은 별도 check:gemini로 검증하며 일반 자동/브라우저 검사는 대역을 쓴다. 실제 휴대폰 키보드·외부 접속 검증과 구분한다.
