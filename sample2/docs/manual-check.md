# 직접 확인할 부분

자동 검사는 저장·재시작·중복 요청·충돌·과거 보존·제안 확인과 화면 동작을 다룬다. 직접 확인은 사용감과 한글 입력 중심으로 진행하면 된다. 현재 Gemini 설정이 있으면 실제 AI가 루틴 추가·삭제를 해석한다. 기존 사용감 확인에 이어 아래 자연어 예시를 확인하면 된다.

## 실행

저장소 루트에서 Node 24.18.1 이상 24 계열을 사용한다.

```bash
npm --prefix sample2 start
```

`http://localhost:8787/sample2/`를 연다. 이미 같은 서버가 실행 중이면 주소만 열면 된다. 직접 실행한 서버의 종료는 Ctrl+C다. 화면에서 새로 넣은 테스트 자료도 DB에 남으며 재실행 때 유지된다.

설정을 바꾸려면 `sample2/.env.example`을 `sample2/.env`로 복사해 PORT·DIARY_DB_PATH를 정한다. 기본값으로 테스트하면 복사할 필요 없다. 현재 서버는 `.env`의 GEMINI_API_KEY·AGENT_MODEL·제한 시간을 사용한다. 키와 모델을 모두 비우면 각본 대역으로 실행한다.

## 3~5분 확인

1. **기록 입력:** 루틴을 눌러 O 또는 X를 기록하고 수정해 본다. 글쓰기 회고에 한글을 입력해 저장한다. 창 크기·문장 입력·저장 피드백이 자연스러운지 확인한다. 새로고침 뒤에도 답변이 보여야 한다.
2. **채팅의 항목 관리:** `생활 루틴에 테스트 명상 항목 추가해줘` → 미리보기 → 취소를 눌러 본다. 다시 요청하고 확인하면 항목 관리에 생겨야 한다. 그 항목을 어제 날짜로 한 번 기록한 뒤 `테스트 명상 항목 빼줘` → 확인하면 현재 목록에서 없어지고 과거 날짜의 기록·리포트는 남아야 한다.
3. **제목·일정:** 회고의 ‘내일의 제목’을 작성한 뒤 다음 날 홈을 확인한다. 미래 날짜에 일정을 넣고 달력에서 날짜를 바꿔 본다. 내용과 날짜 구분이 기대한 사용 방식인지 확인한다.

이상하면 사용한 주소, 누른 순서, 기대 결과와 실제 결과를 알려주면 된다. API 키는 메시지나 캡처에 포함하지 않는다.

실제 휴대폰 키보드 확인은 휴대폰 접속을 마련한 이후에 필요하다. 현재 서버는 본인 PC 로컬 접속용이다. 여러 사용자 로그인·기기 동기화·자유로운 AI 상담·이전 대화 기억은 현재 테스트 대상이 아니다.

## Gemini 연결 후 자연어 확인

채팅 상단에 Gemini가 보이는지 확인한 뒤 다음 요청을 한 가지씩 보내 본다.

- `생활 쪽에 매일 5분 명상하는 습관을 넣어줄래?` → 해석된 이름·목차 확인 → 취소 또는 확인.
- 항목 이름을 명시해 `매일 5분 명상은 이제 목록에서 빼 줘. 지난 기록은 남겨줘.` → 삭제 미리보기 → 확인.
- `그거 지워줘` → 대상을 추측해 삭제하지 않고 이름을 다시 요청해야 한다.

요청을 다르게 이해했다면 확인을 누르지 말고, 입력한 문장과 보여준 제안 내용을 알려주면 된다. 같은 대화에서 앞말을 기억하는 기능은 아직 없다. 일정·리포트 조회는 기존 요청 예시를 사용한다.
