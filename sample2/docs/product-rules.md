# 습관 다이어리 제품 규칙

기준: 2026-10-23. [인덱스](../INDEX.md)에서 사용하는 현재 제품 기준이다. UI의 수치·색상·배치는 [DESIGN.md](../DESIGN.md)를 따른다. 구현 상태와 목표가 다른 채팅 삭제는 [루틴 도구 계약](routine-tools.md)에 구분한다.

## 용어와 개인 MVP 범위

- 목차는 루틴을 묶는 큰 분류, 항목은 문항 정의, 답변은 특정 날짜에 남긴 응답이다.
- 항목 추가·삭제와 날짜별 답변 입력·지우기는 서로 다른 기능이다.
- 개인용으로 시작한다. 여러 사용자용 계정·권한·사용자 간 비교는 이후 확장 범위이며 현재 구현으로 표시하지 않는다.
- 현재 화면과 기능을 기준으로 개선한다. 새 채팅 도구의 범위를 좁힌다고 기존 일정·리포트 등의 기능을 삭제하지 않는다.

## R1 기록과 완료

- O는 실천, X는 미실천이며 둘 다 답변 완료다. 미선택은 미기록이다. 표시 버튼은 O/X를 사용한다.
- O/X, 단일 선택지, 글쓰기, 1~5점 응답을 지원한다. 점수는 주관적 평가이며 실천율에서 자동 산출하지 않는다.
- 일부만 제출할 수 있다. 제출하지 않은 항목의 기존 답변은 유지한다. 답변 지우기는 해당 답변을 미기록으로 되돌린다.
- 홈은 완료된 목차·항목을 회색으로 남기며 수정 가능하다. 전체·목차 기록창은 미기록 항목을 한 화면에 모으고, 모두 기록했다면 전체 답변을 확인·수정한다.
- 루틴 기록은 오늘과 과거에만 가능하다. 날짜 조회만으로 기록이나 체크 상태를 바꾸지 않는다.

## R2 날짜별 문항과 과거 보존

- 저장할 때 문항·선택지·목차의 사본을 날짜별로 보관한다. 현재 이름·응답 형식·목차를 수정해도 과거 저장일의 구성은 유지한다.
- 오늘은 현재 설정을 반영하되, 이미 답한 항목은 당시 문구와 형식을 유지한다. 삭제 표식이 있는 항목은 오늘 목록에 재등장하지 않는다.
- 기록 없는 과거 날짜를 처음 작성하면 현재 활성 항목을 사용한다.
- 일부 답변을 추가 저장할 때도 이전에 삭제된 항목의 날짜별 사본과 답변을 누락시키지 않는다.

## R3 항목 관리와 삭제

- 사용 중지는 관리 목록에 남고 다시 사용할 수 있다. 기존 답변을 보존한다.
- 항목 삭제는 현재 루틴·관리 목록에서 제거하되 날짜별 문항 사본·답변·리포트를 보존한다. 답변 자체를 지우는 기능과 혼동하지 않는다.
- 현재 구현은 기록 있는 항목에 `deleted:true, active:false`를 남기고, 한 번도 답하지 않은 항목의 정의는 제거한다. 다른 저장 방식에서도 같은 사용자 동작을 유지한다.
- 삭제한 항목은 채팅 대상에서 제외한다. 같은 이름으로 새로 만든 항목은 새 ID를 사용하며 과거 항목의 답변을 이어받지 않는다.
- 항목이 없는 목차만 관리 화면에서 삭제할 수 있다. 기록 보존용 삭제 표식만 남은 목차는 비어 있는 것으로 본다.
- 새 채팅 삭제의 의미는 이 항목 삭제 규칙을 따른다. 현재 서버 채팅도 같은 공통 항목 삭제 기능을 호출한다.

## R4 제목과 일정

- 작성 날짜 D의 ‘내일의 제목’은 D+1 홈에 표시되는 80자 이내 한 줄 다짐이다. 일반 회고와 구분한다.
- 홈 제목은 전날 답변을 우선한다. 오래된 `dayTitles` 사본이나 예시가 전날 답변을 덮지 않는다.
- 상단 제목 수정·삭제는 해당 전날 답변에도 반영한다. 미래 작성일의 루틴 응답은 미리 만들지 않고 계획 제목으로 남긴다.
- 제목 내용이 바뀌면 체크를 초기화한다. 제목 체크만 바꾸는 것은 루틴 응답과 점수를 변경하지 않는다.
- 일정은 날짜와 내용이 있으며 해당 날짜에만 표시한다. 홈 상단 카드와 달력에서 추가한다. 업무·공부 목차에 중복 배치하지 않는다.
- 미래 날짜 조회·제목 편집·일정 등록/편집을 허용한다. 달력과 홈을 전환해도 선택 날짜를 유지한다.
- 제목·일정 완료 체크는 해당 날짜부터 가능하다. 일정을 다른 날짜로 옮기면 그 일정의 체크를 초기화하고, 단순 조회는 체크를 유지한다. 자동 이월은 없다.
- 이전 여러 줄 `messages`는 호환 자료다. 임의로 제목이나 일정으로 재분류하지 않는다.

## R5 집계와 조회

- 리포트는 선택 날짜를 끝으로 최근 7일 또는 30일이다. 채팅의 상대 날짜는 실제 오늘 기준이며 이번 주는 월요일부터 오늘까지다.
- 기록한 날은 답변이 하나 이상 있는 날짜다. 응답 완료 수는 O/X·선택·글·점수를 포함한다.
- 점수 평균은 기록된 점수 응답들의 평균이다. 같은 날 점수 항목이 여러 개이면 그래프는 그날 평균을 표시한다. 미기록을 0점으로 채우지 않는다.
- 루틴 실천은 O/X만 집계한다. 미기록 수는 저장된 날짜별 문항 구성에 포함됐지만 답하지 않은 항목 기준이다. 기록을 전혀 시작하지 않은 날의 예정 항목 수를 임의로 만들어내지 않는다.
- ‘남겨둔 생각들’은 글쓰기 회고만 표시한다. 선택지·내일의 제목·일정은 제외한다.
- 숫자는 저장 데이터로 계산한다. AI가 실천 여부·점수·실패 원인을 추측해서 기록하거나 집계하지 않는다.

## R6 예시와 테스트 입력

- 기본 예시는 최근 2주 가상 기록이며 직접 입력과 함께 저장되는 하나의 화면이다. 예시/개인 전환 UI를 다시 추가하는 합의는 없다.
- 사용자 최신 합의: 지금까지 직접 넣은 내용은 테스트 입력이므로 제거해도 된다. 기본 예시를 살려 시작할 수 있으며 기존 개인 입력의 완전한 이전은 MVP 선행 조건이 아니다.
- 이 허용은 현재 테스트 자료 정리 범위다. 이후 새로 작성한 기록을 새로고침·업데이트마다 초기화하는 정책이 아니다. 항목 삭제 때 과거 답변을 보존하는 R3도 계속 유지한다.
- 초기화를 수행할 때 대상 주소·저장 키·범위를 먼저 파악하고, 지정된 다이어리 자료만 처리한다. 다른 프로젝트나 브라우저 전체 데이터를 지우지 않는다. 이 문서 작성 시점에는 초기화하지 않았다.
- 이전 브라우저 초기화/통합 코드는 기존 직접 입력을 우선했다. 현재 서버는 새 DB에만 예시를 준비하고 기존 localStorage를 읽거나 지우지 않는다. 기존 개인 테스트 입력은 자동 이전하지 않는다.
- 예시와 사용자 입력의 출처가 답변별로 완전히 분리돼 있지 않다. 기존 상태에서 직접 입력만 정확히 자동 분리할 수 있다고 가정하지 않는다.

## R7 저장 결과

- 저장에 실패하면 성공을 표시하거나 작성 중인 창을 닫지 않는다.
- 현재 서버는 revision으로 다른 탭과 오래된 수정의 덮어쓰기를 막고 입력을 유지한 채 재확인한다.
- UI 조회, 탭 이동, 날짜 조회로 기록을 변경하지 않는다. 최초 예시 준비와 명시적인 호환 갱신은 별도 경로다.
- 현재 화면과 채팅의 확정 변경은 HTTP를 거쳐 SQLite에 저장한다. 재접속·프로세스 재시작·화면 재조회와 실제 파일 저장을 검증한다. 세부 연결은 [HTTP 계약](http-contract.md)을 따른다.
