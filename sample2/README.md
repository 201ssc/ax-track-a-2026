# 하루의 결 · 습관 다이어리

`sample2/`에 만든 독립적인 습관 기록 웹앱. 예시 데이터가 기본이며, 하나의 다이어리에서 수정·추가하며 체험한다. 이름은 이번 시안의 임시 이름이다.
**새 세션은 [INDEX.md](INDEX.md) → [HANDOFF.md](HANDOFF.md)를 먼저 읽는다.** 인덱스에서 작업별 규칙·수정 범위·완료 확인 방법을 찾고, 인수인계에서 현재 구현 상태를 확인한다.
현재 제품 규칙은 [제품 규칙 문서](docs/product-rules.md), 첫 채팅 도구 목표는 [루틴 항목 도구 계약](docs/routine-tools.md), 합의의 변경 이력은 [DECISIONS.md](DECISIONS.md)에 있다.

개인용 MVP의 HTTP·화면·SQLite 저장과 채팅 제안/확인 연결까지 구현했다. Gemini 설정이 있으면 루틴 추가·삭제는 실제 AI로 해석하고, 기존 일정·목차·조회는 각본 기능을 유지한다. 첫 루틴 도구는 항목 자체의 추가·삭제다. 과거 답변과 집계는 보존한다.

현재 연결은 [HTTP 계약](docs/http-contract.md), 명령·오류는 [명령 계약](docs/command-contract.md), 직접 확인할 내용은 [직접 테스트](docs/manual-check.md)에 있다.

화면은 [shadcn/ui](https://ui.shadcn.com/)를 참고해 흰색·회색 카드, 얇은 테두리, 초록색 강조색, 통일된 선 아이콘과 입력창으로 정리했다. 적용 기준과 참고 캡처는 [DESIGN.md](DESIGN.md)에 있다. 기존 정적 앱에 스타일을 적용했으며 별도 UI 라이브러리 설치나 빌드는 필요 없다.

## 화면 열기

Node 24.18.1 이상 24 계열에서 저장소 루트 기준으로 실행한다. 별도 패키지 설치·빌드는 필요 없다.

```bash
npm --prefix sample2 start
```

**http://localhost:8787/sample2/**

서버 종료는 직접 실행한 터미널의 Ctrl+C다. 같은 서버가 실행 중이면 주소만 연다. 현재 앱은 API를 사용하므로 Python 정적 서버 8765나 HTML 파일 직접 열기로는 동작하지 않는다.

환경 설정은 [sample2/.env.example](.env.example)을 `.env`로 복사해 사용한다. 현재 사용하는 값은 PORT·DIARY_DB_PATH·Gemini 키/모델/제한 시간이다. 기본 DB 경로는 사용자 데이터 디렉터리의 `iruo-habit-diary/diary.sqlite`이며 시작 로그에 표시한다. 실제 `.env`는 Git에서 제외하고 `.env.example`만 공유한다. GEMINI_API_KEY와 AGENT_MODEL을 채우고 재시작하면 실제 Gemini로 루틴 요청을 해석한다. 둘 다 비우면 각본 대역, 하나만 채우면 설정 오류다. 실제 호출 범위·오류·검증은 [Gemini 계약](docs/gemini-contract.md)에 있다.

PC에서도 최대 430px의 휴대폰 폭을 기본으로 표시한다. 실제 휴대폰에서는 화면 너비에 맞춰 표시하며, 기록·리포트·관리·입력창 모두 같은 모바일 구성을 사용한다.

주 메뉴 4개는 화면 하단에 고정한다. 스크롤 중에도 메뉴를 이동할 수 있고, 메뉴 전환 시 새 화면의 맨 위로 이동한다. 본문과 채팅 입력창이 가려지지 않도록 아래 여백을 두며, 저장 알림은 탭 위에 표시한다. 기기 하단 안전 영역도 반영한다.

## 제목과 날짜별 일정

홈 상단은 제목과 일정을 색상으로 구분한다. ‘오늘의 제목’, ‘오늘의 일정’ 같은 설명 제목은 표시하지 않는다. 하루의 제목도 체크할 수 있으며 체크 여부는 루틴 응답 수·점수에 합산하지 않는다.

- **내일의 제목:** 회고 목차에서 80자 이내 한 줄로 작성한다. 작성한 날짜 다음 날 홈 상단의 제목으로 표시한다. 입력창과 저장 안내에 표시될 날짜를 함께 보여준다. 예: 먼저 인사하는 하루.
- **제목 예시:** 기록이 있는 예시 날짜마다 ‘차분하게 시작하는 하루’, ‘말하기 전에 한 번 더 듣는 하루’ 등 다음 날을 위한 짧은 다짐을 넣었다. 오늘의 예시에는 ‘작은 일부터 시작하는 하루’를 넣었다. 회고 문장은 업무·공부 회고에 유지한다. 서버 DB의 예시는 최초 초기화 시에만 생성하며 이후 입력은 유지한다.
- **현재 날짜 제목 수정:** 상단 연필 버튼으로 수정한다. 전날의 ‘내일의 제목’ 답변도 함께 수정된다. 지우면 전날 답변도 미기록으로 돌아간다. 문구가 바뀌면 체크 상태를 초기화한다.
- **날짜가 있는 일정:** 상단 카드의 ‘＋ 일정 추가’를 선택하고 날짜와 할 일을 입력한다. 미래 날짜도 등록할 수 있다.
- **일정 표시:** 지정된 날짜의 홈에 체크리스트로 표시한다. 업무·공부 안에는 일정 추가 버튼이나 일정 목록을 표시하지 않는다. 날짜 옆 달력 토글을 눌러 월별 표시점과 선택 날짜의 일정 목록을 조회·수정·삭제한다. 달력은 미래 날짜도 조회 가능하며 기록 화면에서는 해당 날짜의 일정만 표시한다. 일정을 다른 날짜로 옮기면 그 일정의 체크 상태를 초기화한다. 날짜 조회만 바꿀 때는 저장된 체크 상태를 유지한다. 미완료 일정을 다른 날로 자동 이월하지 않는다.
- **진행 현황:** 루틴 진행 수와 전체 기록 버튼은 상단 카드 아래 작은 영역에 표시한다.
- **이전 기록 보존:** 기존 ‘하루 한 줄’ 답변과 여러 줄의 ‘내일의 나에게’ 기록은 보존한다. 이전 여러 줄 기록은 해당 날짜 제목 편집창의 ‘이전에 남긴 문장’에서 확인할 수 있다. 문장을 제목이나 날짜 있는 일정으로 자동 분류하지 않는다.

## 사용 흐름

- **오늘의 기록:** 목차를 펼치고 하나만 기록하거나 ‘전체 항목 기록하기’를 선택한다. 전체·목차 기록에서는 해당 항목을 한 화면에 펼친다. 한 문항씩 넘기는 단계와 모드 전환은 없다.
- **O/X:** O는 실천, X는 미실천. 둘 다 제출하면 기록 완료다. 홈의 하위 목록에서는 완료 항목도 회색으로 남고 누르면 수정할 수 있다. 미선택은 미기록이다.
- **전체·목차 설문:** 미기록 항목만 모아서 진행한다. 모두 기록한 경우에는 전체 답변을 돌아볼 수 있다.
- **일부 제출:** ‘작성한 항목 저장’로 답한 내용만 저장한다. 건너뛴 항목은 그대로 남는다.
- **홈 하위 목록:** 모든 항목을 표시하며 제출한 항목은 회색으로 표시한다. 항목을 누르면 수정 가능하다. ‘저장한 이 답변 지우기’는 미기록으로 되돌린다.
- **날짜:** 오늘이 기본이다. 상단 날짜 선택기와 좌우 화살표로 과거·미래 날짜를 모두 조회한다. 미래 날짜의 제목과 일정을 확인·편집하고 일정을 추가할 수 있다. 달력/홈 전환 시 선택 날짜를 유지한다. 루틴 기록과 제목·일정 완료 체크는 해당 날짜부터 가능하다. 지난 날짜는 뒤늦게 기록할 수 있다.
- **항목 관리:** 항목명·응답 방식·⋯ 메뉴를 한 줄에 표시한다. 이름을 누르면 수정하고, ⋯ 메뉴에서 수정·중지·순서 이동·삭제한다. 목차 관리도 제목 옆 ⋯ 메뉴를 사용한다. 답변 방식은 O/X, 단일 선택지, 글쓰기, 점수(1~5)다. 하위 선택지를 행별로 수정·추가·삭제하고 ↑/↓로 순서를 바꿀 수 있다. 새 선택지의 시작 예시는 A/B/C/D/기타이며 이름을 자유롭게 바꾼다.
- **중지·삭제:** 중지한 항목은 관리 목록에 남아 다시 사용할 수 있다. 삭제는 모든 항목의 ⋯ 메뉴에서 가능하며 확인 후 현재 루틴과 관리 목록에서 제거한다. 과거 문항 사본·답변·리포트는 유지한다. 항목이 없는 목차를 삭제할 수 있다.
- **리포트:** 선택한 날짜까지 최근 7일/30일의 기록한 날, 응답 수, 점수, O/X/미기록을 보여준다. ‘남겨둔 생각들’에는 글로 쓴 회고만 표시하며 선택지·내일의 제목·일정은 제외한다. 날짜별 기록에서 과거 답변으로 이동할 수 있다.

## Gemini 루틴 요청과 기존 각본 채팅

**http://localhost:8787/sample2/#chat** 에서 기본 예시 기록으로 체험한다.

Gemini 모드에서 루틴 추가·삭제는 자연어를 해석한다. 예: “생활 쪽에 매일 5분 명상하는 습관을 넣어줄래?” 또는 “생활 루틴에 명상 항목 제거해줘.” 기존 해석기의 이름 검색이 실패해도 루틴 요청은 Gemini가 해석한다. 기존 목차·일정·조회는 정해진 표현으로 처리한다. 숫자는 저장된 기록에서 코드로 계산한다. ‘요청 예시 보기’를 누르면 아래 예시를 바로 전송할 수 있다.

- `취미 목차 추가해줘`
- `생활 루틴에 명상 항목 추가해줘` (처음에는 O/X 방식. 항목 관리에서 형식을 수정한다.)
- `비타민 챙기기 항목 빼줘`
- `취미 목차 삭제해줘`
- `이번 달 27일 독서 모임`
- `이번 달 남은 할 일은?`
- `독서 모임을 30일로 변경해줘`
- `이번 주 점수 어때?`
- `어디가 잘 안 되고 있어?`

목차·항목·일정의 변경은 미리보기 후 **확인하고 반영**을 눌러 저장한다. 취소하면 저장하지 않는다. 같은 이름이 여러 개이면 대상을 먼저 고른다. 제안 후 대상이 달라졌다면 최신 상태에서 다시 요청하게 한다. 항목 삭제는 기록 유무와 관계없이 현재 목록에서 제거하며, 과거 답변은 보존한다.

채팅의 ‘빼줘’는 관리 화면과 같은 항목 삭제 기능을 사용한다. 사용 중지·재개는 관리 화면의 별도 기능이다. 이미 삭제한 항목은 채팅 변경 대상에서 제외한다.

지원 날짜: 오늘·내일·모레, 이번 달/다음 달 N일, M월 N일, YYYY-MM-DD. 월을 생략한 ‘30일’은 실제 오늘이 속한 달로 해석하고 확인 카드에 절대 날짜를 표시한다. 다른 자유로운 표현은 추측해서 실행하지 않는다.

이번 주는 월요일부터 실제 오늘까지다. 점수는 기록된 응답만 평균을 내며, 루틴은 O/X와 미기록을 나눠 설명한다. 미기록 날짜를 미실천으로 보거나 실패 원인을 지어내지 않는다. 이번 달 남은 일정은 실제 오늘부터 월말까지의 미완료 일정이다.

변경 결과는 하나의 통합 다이어리에 남는다. 대화 화면은 탭 안에서 유지되지만 새로고침하면 사라진다. 서버의 제안·적용 결과는 재시작 후에도 유지되며 확인 재시도로 중복 적용하지 않는다. 대화 원문은 별도로 저장하지 않는다.

## 예시 데이터가 기본인 한 화면

**http://localhost:8787/sample2/** 를 열면 최근 2주 예시가 포함된 하나의 다이어리가 열린다. 빈 화면과 예시 화면을 전환하는 기능은 제거했다. 이전 `?demo=1` 또는 `?demo=0` 주소도 같은 다이어리로 연결되고 쿼리에서 `demo`를 제거한다.

새 방문자에게는 완료·부분 기록·미기록 날짜, 점수·회고, 제목과 날짜별 일정이 준비된다. 사용 중 수정한 기록은 저장되며 매번 새 예시로 재설정하지 않는다. 작은 ‘예시 기록 포함’ 배지로 최초 데이터의 성격을 표시한다.

화면과 채팅은 서버의 SQLite를 사용한다. 같은 DB에 연결한 로컬 탭·브라우저는 같은 기록을 본다. 기존 브라우저 localStorage는 자동 이전·삭제하지 않는다. 예전 초기화·호환 자료는 `prototype.mjs`와 관련 단위 검사에 남겨두었으며 현재 화면 진입 경로에서 호출하지 않는다.

## 22일과 23일의 제목 명칭이 달랐던 이유

과거 날짜는 당시 문항 사본을 표시하고, 오늘은 최신 설정을 표시했기 때문이다. 최신 설정의 이름만 바꿔서는 과거 사본의 ‘하루 한 줄’에 적용되지 않았다.

이제 과거의 기본 ‘하루 한 줄’도 화면에서는 ‘내일의 제목’으로 표시한다. 다음 날짜의 홈은 전날 해당 항목의 답변을 직접 읽으므로 기존 기록을 다시 저장하지 않아도 연결된다. 별도로 남은 예시 제목과 충돌하면 전날 답변을 우선한다. 로드 시 원래 답변이나 문항 사본은 덮어쓰지 않는다. 같은 날 이전 항목과 새 제목 항목이 모두 있으면 이전 답변은 ‘이전 회고’로 남겨 새 제목과 구분한다.

## 데이터 범위

- 첫 실행의 4개 목차와 12개 문항 및 최근 2주 가상 기록이 기본 예시다. 기존 기록이 있으면 그 내용을 우선 보존한다.
- 실제 입력은 서버 DB 파일에 저장한다. 브라우저 저장소 삭제와 별개이며 같은 로컬 서버를 쓰는 다른 브라우저에서도 보인다. 외부 기기 접속·로그인은 아직 없다.
- 오늘의 문항 관리 변경은 현재 구성에 반영된다. 제출한 답변은 당시 문구와 형식을 유지한다. 지난 날짜에 저장된 문항 구성은 이후 편집으로 바뀌지 않는다. 과거 미기록 날짜를 처음 작성하면 현재 활성 항목을 사용한다.
- 루틴 실천 집계는 O/X만 대상으로 하며 글·선택·점수 응답을 실천으로 추측하지 않는다. 미기록 날짜를 점수 0으로 계산하지 않는다.
- 미기록 항목 수는 저장된 날짜별 문항 구성 기준이다. 기록을 전혀 시작하지 않은 날에는 어떤 루틴이 예정되었는지 확정하지 않는다.
- 저장 오류 시 성공으로 표시하거나 입력창을 닫지 않는다. 다른 탭에서 수정하면 revision 충돌로 덮어쓰기를 막고 입력을 유지한 채 재확인을 받는다.
- 로컬 서버 DB·공통 명령·제안 저장은 구현했다. Gemini 루틴 해석도 연결했다. 계정, 외부 기기 동기화, 자동 조언·대화 기억은 미구현이다. 가계부의 처리 원칙을 참고하되 FastAPI 서버는 재사용하지 않는다.

## 파일

- `index.html`: 문서와 앱 외곽
- `boot.js`: 시작 실패를 빈 화면 대신 안내하고 다시 불러오기 제공
- `update-assets.py`: 앱·모듈·스타일의 캐시 버전을 함께 갱신
- `styles.css`: 반응형 스타일
- `demo.mjs`: 최초 기본 예시를 위한 2주치 가상 기록 생성
- `prototype.mjs`: 이전 브라우저 데이터 통합 호환 함수. 현재 서버 화면에서는 호출하지 않음
- `model.mjs`: 기본 항목, 기록 저장 규칙, 날짜별 문항 보존, 리포트 집계
- `app.js`, `api.mjs`: 화면과 사용자 조작, 비동기 HTTP 저장·재시도
- `chat.mjs`, `server/chat-service.mjs`: 각본 해석·조회·서버 제안 연결
- `server/store.mjs`: SQLite 저장·수정 번호·중복 방지·제안·백업
- `server/http.mjs`, `server/start.mjs`: 로컬 HTTP와 실행·설정
- `tests/chat.test.mjs`: 제안 전 불변·확인 적용·동명 구분·오래된 제안 차단·집계·회고 필터 검증
- `tests/chat.cjs`: 채팅과 앱 화면 연결·모바일·저장 실패 검증
- `tests/prototype.test.mjs`, `tests/prototype.cjs`: 예시 기본값·단일 주소/저장·기존 데이터 보존·과거 제목 명칭/다음 날 연결 검증
- `tests/model.test.mjs`: 완료·미실천 구분, 부분 저장, 과거 보존, 리포트 검증
- `tests/browser.cjs`: 실제 브라우저의 기록·관리·리포트·모바일·저장 오류 검증
- `tests/messages.cjs`: 한 줄 제목·체크 저장·날짜별 일정 등록/수정·루틴 집계 분리·이전 키 보존 검증

의존성 설치와 빌드 없이 실행하며 외부 폰트·CDN은 요청하지 않는다. Gemini가 설정된 경우 서버가 Google 모델 API를 호출한다. 앱의 로컬 HTTP API는 사용한다.

## 검증

```bash
node --test sample2/tests/*.test.mjs
```

브라우저 검사는 개발용 Playwright와 Chromium이 필요하다. 아래 설치는 실행 앱의 의존성을 바꾸지 않으며 `node_modules`는 Git에서 제외한다.

```bash
cd sample2
npm install --no-save --package-lock=false playwright
npx playwright install chromium
npm run test:browser
```

이미 설치한 환경에서는 `PLAYWRIGHT_MODULE`에 Playwright 모듈 절대 경로, `BROWSER_EXECUTABLE`에 Chromium 실행 파일 경로를 지정해 사용할 수 있다. 위 명령의 검증 기준과 별도 실제 호출 명령은 다시 저장소 루트에서 실행한다.

검사는 분리된 새 브라우저 컨텍스트에서 실행하므로 사용자 브라우저의 기록을 건드리지 않는다. 결과 PNG는 `/tmp/habit-sample2-*.png`로 저장된다.

전체 브라우저 검사는 같은 환경 변수로 `npm --prefix sample2 run test:browser`를 실행하면 된다. 각 검사는 임시 서버·DB를 자동 준비하고 종료한다. 별도 8765/8787 서버를 필요로 하지 않는다. 같은 환경 변수로 `startup`, `browser`, `messages`, `management`, `future-dates`, `chat`, `prototype`, `sync`, `gemini`의 `.cjs`를 실행한다. `server-fixture.cjs`는 공통 준비 모듈이다.

현재 자동 검사 결과와 과거 결과는 [HANDOFF.md](HANDOFF.md)를 따른다. 일반 테스트는 실제 모델을 호출하지 않는다. 별도 `npm --prefix sample2 run check:gemini`는 실제 Gemini 4건을 임시 DB로 검사하며 호출 비용/한도를 사용한다. 실제 휴대폰 키보드·외부 접속·폭넓은 모델 품질 검증과 구분한다.
